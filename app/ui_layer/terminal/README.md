# CraftBot terminal edition

A React + Ink client of the CraftBot backend. It replaces the old line-based
CLI. `python run.py --tui` starts the backend in terminal mode and runs this
client in the same console; `python craftbot.py tui` attaches it to a
background service.

## How it fits together

- **Backend.** The same Python backend as the browser edition, started with
  `CRAFTBOT_FRONTEND=terminal` (`app/edition.py`). That edition fixes, once
  per process, what the agent is told about the user's screen and leaves
  browser-only actions (`render_ui`) out of the action space. The backend's
  output goes to `<state>/logs/backend.log`; the client owns the console.
- **Protocol.** The browser's own WebSocket protocol on `ws://localhost:<port>/ws`,
  with the same session-token handshake. The client also sends `client_hello`
  (`src/runtime/runtime.tsx`): the backend records its capabilities on that
  socket and sends capability-gated frames only to clients that asked, so the
  browser never receives anything new.
- **State.** The browser frontend's Redux slices, imported read-only
  (`src/state/store.ts`), plus the terminal's `tui` slice. `build.mjs` swaps
  the two browser-only modules the store imports (`i18n/config`,
  `utils/connection`) for `src/platform/*`, and `src/platform/globals.ts`
  provides the few browser globals the store touches. Never edit the browser
  frontend for this client.
- **Rendering.** One Ink root at a time (`src/runtime/runtime.tsx`):
  - the chat root renders inline on the main screen. Finished messages and
    settled action chunks are written into the terminal's own scrollback once
    (`src/chat/transcriptWriter.ts`), so native selection, copy and search
    work. Below that is a small live region: the running turn, the pinned
    question, toasts, the composer and the status line. It stays well under
    the viewport height so Ink never falls back to clearing the screen;
  - the screen root renders on the alternate screen while any full-screen
    screen is open (sessions, settings, memory, workspace, dashboard, browser,
    Agent Apps). Screens form a stack.
  Swapping clears the old root's frame first, so nothing stale is left in
  scrollback.

## Conventions

- **Keys.** Each root has one `useInput`. The chat routes keys to global
  shortcuts, the slash popup, the question box and the composer. A screen
  registers one handler with `useScreenKeys` and returns `true` for the keys
  it used; unused keys fall through to the screen root (Esc back, q close,
  Ctrl+P palette, ? help). A screen with a focused text field calls
  `setTextFocus(true)` so single letters are not taken as shortcuts.
- **Screens.** Wrap the content in `ui/Frame` (a bordered panel: title and
  aside set into the top edge, key hints under it; lay rows out to the
  `columns` from `useScreen()`, which is already inside the border). Use
  `ui/list.ts` for selection, `ui/selection.tsx` for the pointer and the
  selection chip, `ui/TextField.tsx` for inputs and `ui/Confirm.tsx` for
  anything destructive (cancel is the default).
- **Text.** Measure and cut with `src/text/width.ts`, never `.length`: CJK
  characters are two cells wide.
- **Glyphs and colors.** Use `src/theme/theme.ts`: `glyphs()` for every mark,
  colors through `ink.*` and `tone.*` so NO_COLOR works, and never color alone
  for meaning. No emoji, ever. The glyph set follows the terminal: `modern`
  where it has font fallback, `console` on the classic Windows console (only
  characters both Lucida Console and Consolas draw, listed in
  `src/text/consoleCharset.ts`, regenerated by `node scripts/console-charset.mjs`),
  `ascii` as a last resort; `CRAFTBOT_GLYPHS=modern|console|ascii` overrides.
  On the console a last pass on the output (`src/text/glyphSafe.ts`) swaps any
  other symbol for a look-alike of the same width, so nothing draws as a box
  with a question mark.
- **Layout.** The visual system is written up in
  `research_notes/CraftBot terminal UI rewrite/tui_visual_design.md` (section
  5): a two-cell gutter under every block, one blank line only where the kind
  of content changes, the brand orange for the agent, focus and anything live,
  boxes only for decisions, one spinner on screen.
- **Strings.** Every user-facing string goes through i18next. Terminal-only
  strings live in this package's `locales/<lang>/<namespace>.json`; every JSON
  file there is a namespace (`tui`, `tuiSettings`, ...) and is bundled with
  the browser's own catalogs, which can be used too. Keep all 7 languages in
  step (`node scripts/check-locales.mjs`).
- **Copy.** No em dashes. Inside Agent App screens the agent is "your AI
  agent", never "CraftBot".

## Commands

```
npm install
node build.mjs           # dist/craftbot-tui.mjs (minified); --dev for a source map
npm run typecheck
npm test                 # unit tests (vitest)
node scripts/check-locales.mjs                # every namespace in all 7 languages

# Drive the built client in a real pseudo-terminal (ConPTY on Windows):
node test/pty/smoke.mjs   <port> <stateDir>   # first screen
node test/pty/keys.mjs    <port> <stateDir>   # popups, screens, back to the chat
node test/pty/screens.mjs <port> <stateDir>   # open every screen once
node test/pty/narrow.mjs  <port> <stateDir>   # small terminal and resize
node test/pty/chat.mjs    <port> <stateDir>   # a live chat turn (calls the model)
node test/pty/switch.mjs  <port> <stateDir>   # new chat, switch, /clear leave no old conversation
node test/pty/look.mjs    <port> <stateDir> [modern|console|ascii]   # print the main surfaces
CRAFTBOT_HOME=<home> node test/pty/owner.mjs <python> <repo> <port>   # run.py --tui end to end
node test/harness/run-app-screen.mjs <projectDir> <appPort>           # an Agent App screen, read-only
node test/harness/run-chat-pane.mjs [width] [height] [glyphs] [app]  # the Agent App chat pane, seeded, offline
```

The Agent App view engine shared with `agent-app view` lives in
`agent-app/view` (`node --test agent-app/view/src/view.test.ts`).

Run end-to-end checks against an isolated backend, never your own CraftBot:
seed a scratch `CRAFTBOT_HOME` from git-tracked files only, then
`python run.py --tui --backend-only --backend-port 7946`.
