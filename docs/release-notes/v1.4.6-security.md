# v1.4.6 release notes: security section (draft)

Copy into the v1.4.6 release PR and GitHub Release.

### Security

- **Settings > Security:** choose Standard, Enhanced or Strict. Standard, the default, never prompts; Enhanced and Strict keep the agent and its tools away from your keys, check its web requests and start only MCP servers saved in Settings. [How the levels work](../security-levels.md)
- **Approve risky actions:** turn Auto mode off to approve commands, outgoing messages, changes to CraftBot's own setup and the use of stored credentials on a card in the chat, in the browser and the terminal.
- **More protections at Enhanced and Strict, each also a setting of its own:** review risky commands (an approval card, or a reviewer model with Auto mode on); limit what other people's messages and scheduled tasks can do; keep the file tools away from SSH, cloud and system credentials and `.env` files; hide secrets in tool results; keep memory files written from outside content out of the prompt; block private addresses in the built-in browser too; scan skills before installing them; check MCP packages for known malware; verify downloads against their checksum.
- **Approval cards:** "Allow for this session" covers only that exact command, and hidden characters are shown.
- **Security check:** Settings > Security lists the state of your install (file permissions, network exposure, inbox and Discord exposure, MCP changes, the audit chain) and fixes what it safely can.
- **Fixed:** an MCP server could run code inside CraftBot through a crafted tool name (versions 1.2.0 to 1.4.5). Thanks to @rohantiwari9573 for reporting it. See the security advisory.
- **Always on:** commands that do damage no approval can undo (deleting `/` or your home folder, wiping a disk) are refused; outside content reaches the model marked as data; CraftBot's secrets are masked in logs; a tamper-evident audit log records approvals and security changes; Discord owners are recognized by user ID, never by display name or role name; files holding your keys are readable by your user only; a profile bundle can no longer hand your saved keys to a different command; the interface's session token is served to CraftBot's own page only.
- **New:** [SECURITY.md](../../SECURITY.md) explains how to report a vulnerability privately.

### Upgrade notes

- The terminal client now reads the session token from an owner-only file. Other local programs that fetched `/api/session-token` (for example the Omarchy bar widget) need an update to read `<state dir>/run/session-<port>.token`.
- Discord: display names no longer match the Self or Third-party user lists (usernames do), and "Self roles" no longer grant owner rights; people with those roles still reach the agent, as third-party messages. Add your user ID under Self user IDs, or message the bot once with a listed username to have it recorded.
- At Enhanced and Strict, the agent's file tools can no longer read or edit `settings.json` or `mcp_config.json`; it uses `read_settings` (keys hidden) and asks you to change settings in the Settings page.
